# Race Condition - Состояния гонки

Этот пример демонстрирует проблему race condition (состояния гонки) в Go и способы её решения.

## Что такое Race Condition?

Race condition возникает, когда несколько горутин одновременно обращаются к одной и той же переменной, и результат зависит от порядка выполнения операций.

## Файлы в проекте

- `counter.go` - функции с безопасным и небезопасным доступом к счетчику
- `race_condition_test.go` - тесты демонстрирующие проблему и её решение

## Демонстрируемые концепции

### 1. Небезопасный код
```go
func UnsafeIncrement() {
    counter++  // НЕ атомарная операция!
}
```

### 2. Безопасный код с mutex
```go
func SafeIncrement() {
    mutex.Lock()
    counter++
    mutex.Unlock()
}
```

## Команды для запуска

```bash
# Обычный запуск тестов
go test -v

# Детекция race condition (ОБЯЗАТЕЛЬНО!)
go test -race

# Бенчмарки для сравнения производительности
go test -bench=.

# Запуск с race детектором и подробным выводом
go test -race -v
```

## Что происходит

1. **Небезопасный счетчик**: может показать любое число от 1 до 100
2. **Безопасный счетчик**: всегда показывает правильный результат (100)
3. **Race detector** обнаруживает проблемы в небезопасном коде

## Важные замечания

- **ВСЕГДА** используйте `-race` флаг при разработке
- Race condition может проявляться не всегда
- Mutex добавляет накладные расходы, но обеспечивает безопасность
- Проблема характерна для всех языков с многопоточностью

## Альтернативные решения

Кроме mutex можно использовать:
- `sync/atomic` для простых операций
- Каналы (channels) для синхронизации
- `sync.Once` для однократной инициализации
